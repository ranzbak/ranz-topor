## Rules (every `.kicad_pro`)

- 4 copper layers, KiCad layer types all signal: topor's default roles F.Cu signal / In1.Cu gnd / In2.Cu pwr / B.Cu signal, so only F.Cu and B.Cu route.
- The unrouted problem of bga_plane_balls shows 2 isolated_copper (the planes before any via reaches them).
- Net class Default = Board Setup minimums (no necking, no via-size trap): see each pattern.
- Destinations: PTH pads 0.6 / 0.3 at 1.0 mm in a row on each side, ordered like the escape lines (no forced crossing, no forced via). Price = mm + 25 mm per via. Copper to edge 0.50, hole clearance 0.20.
- U1 has an F.CrtYd rectangle half a pitch around the outer ball centres; only bga_neckdown has a .kicad_dru.

## The user's BGA rules (2026-11-12) and how `rule_faults()` checks them

Every expected answer has 0 faults (asserted when generating); the PNG of a routed board marks each fault in magenta (circle = ball, x = R1 / short spot, square = R2 / R3 via) and lists them by rule in the footer.

- **R1** no trace passes through or over another ball's via (real widths; DRC clearance and drawn overlap). Every track segment (real width) against every via of another net (vias are on all layers): copper gap < the clearance that applies (net class, or the courtyard rule) = fault; gap <= 0 = drawn overlap (a short).
- **R2** a dog-bone via sits at the centre of the open space between 4 balls (max clearance), never near the pad. A via inside the BGA box that serves a ball (nearest ball of its net within one pitch) must be within 0.05 mm (VIA_CENTRE_TOL) of an open-space centre.
- **R3** dog-bones point outward from the package centre per quadrant (top-left quadrant -> up-left, ...). The sign of (via - ball) on both axes must equal the sign of (ball - package centre) (outward_dirs()).
- **R4** one via per plane ball (GND / PWR), no shared vias. Every plane ball needs a via of its own (nearest plane ball of that via); a via within reach of two plane balls that have no other via = shared.
- **R5** via style is a production option: dog-bone by default, via-in-pad only with option via_in_pad. A via within VIA_CENTRE_TOL of its ball centre is via-in-pad: a fault while the option via_in_pad is off (default).
- **R6** a .kicad_dru courtyard rule (neckdown) may relax width / clearance inside the BGA. bga_neckdown carries the rule; the checker uses its clearance for every pair of which one item touches U1's courtyard, as KiCad does; kicad-cli DRC is the judge.
- **R7** signals on the plane layers (In1 / In2 of a 4-layer board) are allowed but very costly: expected answers never use them. A track of a non-plane net on In1.Cu / In2.Cu (topor's default 4-layer plane roles).
- **short** copper of two nets touching (shapely overlap on one layer, or KiCad DRC shorting_items). Two nets' copper touching on one layer (shapely: track-track, track-pad, via-pad, via-via; track-via is R1), plus every KiCad DRC shorting_items of the routed board.

**Odd arrays (R3, centre row / column):** a ball on the centre column of an odd array takes the outward diagonal of a clockwise pinwheel (top half -> up-right, right half of the centre row -> down-right, bottom half -> down-left, left half -> up-left, the centre ball up-left); the checker accepts either outward diagonal for such balls. The 6 x 6 patterns have no centre row / column.

**Not built yet (user question):** a 7 x 7 / 8 x 8 array is the first size where one layer cannot escape everything even with one track per channel (Luzin p. 1: 4(n-1) channels vs (n-2)^2 inner balls: 24 < 25 at n = 7, 28 < 36 at n = 8), so 'outer two rings on top, the rest dog-bone' becomes the optimum and the first interesting via_in_pad case; 0.5 / 0.65 mm pitch is the fine-pitch case (eMMC / LPDDR, Zynq U7) where no 0.40 via fits between four balls at all (0.5 x sqrt 2 = 0.71 mm diagonal), so only via-in-pad or micro vias work -- i.e. a pattern whose expected answer depends on the via_in_pad option.

## Literature

- Luzin & Polubasov 2008, 'TopoR: routing PCBs with BGA components' (docs/literature/luzin2008-topor-bga.pdf), PDF p. 1 (journal p. 44): an n x n array has 4(n-1) channels on its periphery and (n-2)^2 inner balls; one layer suffices while 4(n-1) >= (n-2)^2, i.e. up to n = 6 (at n = 7 one channel is missing); a fanout via guarantees no blocking with enough layers, but not on one layer
- Luzin & Polubasov 2008, PDF p. 2 (journal p. 46): pitch 1 mm, pad 0.5 mm, track 0.15 mm, gap 0.15 mm -> one track passes between two balls; outside-in, each layer takes two perimeters plus four inner balls; balls tied to ground / power planes by vias need not be brought to the periphery
- Luzin & Polubasov 2008, PDF p. 4 (journal p. 48): TopoR's BGA model, fig. 9: a via cell is the area between four neighbouring balls, every used ball except the first row has its own cell; requirements: avoid jumpers between neighbouring balls, every ball (except the outer rows) its own via rather than another ball's via of the same net, vias outside the package where possible; lengthening the piece from ball to via is very undesirable because it can block neighbouring balls
- TopoR 5.0 help (docs/literature/eremex-topor50-help.txt, page 2/bga.htm and 4/bga.htm): BGA components are recognised; the smallest via is chosen automatically; one rule for the pad layer and one for the other layers; warning 3005 when a via does not fit between the pads; rectangular grids only
- Luzin & Polubasov 2008, PDF p. 3 (journal p. 47): power and ground balls in the centre of the package simplify routing (fig. 7)
- TopoR 6.3 User Manual (docs/literature/eremex2017-topor63-user-manual.pdf) p. 75 'Routing BGA Components' (same rules as 5.0) and p. 65 (nets to internal plane layers get fanouts only)
- memory planes-are-terminals: an own-net plane is a terminal like a pad, vias on it are always allowed
- memory power-via-rules: smallest Board Setup via with pi x drill >= trace width
- Haas 2026, BGA memory bus (docs/literature/haas2026-bga-memory-bus.pdf) PDF p. 2: the fanout engine offers every ball a stub on its layer or a dog-bone via to the other layer
- KiCad 10 PCB Editor manual, 'Custom design rules' (Board Setup -> Design Rules -> Custom Rules; the neck-down example uses A.intersectsCourtyard('<ref>') with track_width / clearance constraints); conditions are tried for (A, B) and (B, A) (pcbnew/drc/drc_rule_condition.cpp EvaluateFor)
