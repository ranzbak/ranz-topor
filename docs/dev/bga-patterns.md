## Rules (every `.kicad_pro`)

- 4 copper layers, KiCad layer types all signal: topor's default roles F.Cu signal / In1.Cu gnd / In2.Cu pwr / B.Cu signal, so only F.Cu and B.Cu route.
- The unrouted problem of bga_plane_balls shows 2 isolated_copper (the planes before any via reaches them).
- Net class Default = Board Setup minimums (no necking, no via-size trap): see each pattern.
- Destinations: PTH pads 0.6 / 0.3 at 1.0 mm in a row on each side, ordered like the escape lines (no forced crossing, no forced via). Price = mm + 25 mm per via. Copper to edge 0.50, hole clearance 0.20.

|---|---|---|---|

| ring1 | 12 | 12 x F.Cu | 0 |

**Why.** One track fits between two balls (gap 0.50 >= 0.15 + 2 x 0.15). A 6 x 6 has 20 peripheral channels and 16 inner balls (Luzin p. 1: 4(n-1) >= (n-2)^2 up to n = 6). Every channel holds one wire, no wire crosses, no via is needed, so any via would only add 25 mm price.

## Judgement calls needing the user

- bga_one_layer: the user's suggested (a) (outer two rows on F.Cu, inner balls dog-bone) is not the optimum for a 6 x 6 with one track per channel: Luzin p. 1 shows it escapes on one layer; it is drawn as the alternative (4 vias, +100 mm). Luzin p. 4 / TopoR's BGA mode asks 'every ball except the outer rows its own via': read here as a fallback when channels run out, not as a rule that adds vias where the channels are free
- bga_one_layer: each side: 5 ring-0 balls straight out, 3 ring-1 balls through the channel at their outward-diagonal cell, 1 centre ball through the remaining channel; the 4 sides are rotations, so any rotation or mirror of the assignment is equally optimal
- bga_one_layer: destination PTH rows (0.6 / 0.3 at 1.0 mm) connect on every layer, so a router may choose B.Cu at a cost of 1 via per wire; the pad row never forces a via
- bga_plane_balls: own via per plane ball (Luzin p. 4) rather than the cheapest count; the shared-via alternative is drawn (1 GND via, 4 stubs, KiCad DRC clean). Make it an option? (default: own via)
- bga_plane_balls: dog-bone (stub to the cell centre, via there) rather than via-in-pad: Board Setup has no via-in-pad / filled-via capability flag; the hand boards split: HaasoscopePro, ButterStick U4, Glasgow use via-in-pad, ULX3S, ThunderScope, Zynq U2 dog-bone. Via-in-pad would be 0 stub length
- bga_plane_balls: each plane via sits in the cell on the ball's outward diagonal (away from the package centre), as in most ULX3S dog-bones; the cell must not take a channel a signal needs (here none does)
- bga_plane_balls: VCC on the 4 ring-1 corners shows a plane via in ring 1 next to signal channels; the plane nets are power nets only by name (same 0.15 mm stub as the signals, net class Default)
- bga_dogbone: In1.Cu / In2.Cu are planes by topor's default 4-layer roles (signal / gnd / pwr / signal), so the inner balls escape on B.Cu; with all four layers routable, In1 or In2 would be equally good
- bga_dogbone: via cells: ring-1 balls on their outward-diagonal outer cell, the ring-2 ball one cell further in; on B.Cu no track passes between two vias one pitch apart (0.40 < 0.45), so each side keeps one outer cell free for the ring-2 wire. Other free-cell choices (rotations, mirrors) are equally optimal
- bga_dogbone: 0.15 / 0.15 rules with 0.40 pads at 0.8 mm is the zero-channel case (6-mil fab); with the 0.127 / 0.127 the survey boards use, one track fits and the 6 x 6 escapes on F.Cu like bga_one_layer
- bga_dogbone: stub = ball centre to cell centre at 45 degrees (0.566 mm); Luzin p. 4: keep it short so it blocks no neighbour

## Literature

- Luzin & Polubasov 2008, 'TopoR: routing PCBs with BGA components' (docs/literature/luzin2008-topor-bga.pdf), PDF p. 1 (journal p. 44): an n x n array has 4(n-1) channels on its periphery and (n-2)^2 inner balls; one layer suffices while 4(n-1) >= (n-2)^2, i.e. up to n = 6 (at n = 7 one channel is missing); a fanout via guarantees no blocking with enough layers, but not on one layer
- Luzin & Polubasov 2008, PDF p. 2 (journal p. 46): pitch 1 mm, pad 0.5 mm, track 0.15 mm, gap 0.15 mm -> one track passes between two balls; outside-in, each layer takes two perimeters plus four inner balls; balls tied to ground / power planes by vias need not be brought to the periphery
- Luzin & Polubasov 2008, PDF p. 4 (journal p. 48): TopoR's BGA model, fig. 9: a via cell is the area between four neighbouring balls, every used ball except the first row has its own cell; requirements: avoid jumpers between neighbouring balls, every ball (except the outer rows) its own via rather than another ball's via of the same net, vias outside the package where possible; lengthening the piece from ball to via is very undesirable because it can block neighbouring balls
- TopoR 5.0 help (docs/literature/eremex-topor50-help.txt, page 2/bga.htm and 4/bga.htm): BGA components are recognised; the smallest via is chosen automatically; one rule for the pad layer and one for the other layers; warning 3005 when a via does not fit between the pads; rectangular grids only
- Luzin & Polubasov 2008, PDF p. 3 (journal p. 47): power and ground balls in the centre of the package simplify routing (fig. 7)
- TopoR 6.3 User Manual (docs/literature/eremex2017-topor63-user-manual.pdf) p. 75 'Routing BGA Components' (same rules as 5.0) and p. 65 (nets to internal plane layers get fanouts only)
- memory planes-are-terminals: an own-net plane is a terminal like a pad, vias on it are always allowed
- memory power-via-rules: smallest Board Setup via with pi x drill >= trace width
- Haas 2026, BGA memory bus (docs/literature/haas2026-bga-memory-bus.pdf) PDF p. 2: the fanout engine offers every ball a stub on its layer or a dog-bone via to the other layer
